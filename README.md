# Agent Desk Local

현재 PC에서 메인 AI에게 요청하고, 에이전트의 배정·작업·대기 상태와 보고를 확인하는 로컬 대시보드입니다.

## 시작

1. Windows PC에 Node.js 22 이상과 Codex CLI를 설치합니다. `codex login`으로 본인 계정에 로그인하고 `codex login status`로 확인합니다.
2. `Start-AgentDesk.cmd`를 더블클릭합니다.
3. `http://127.0.0.1:4317`에서 사용합니다. 로컬 서버는 숨겨진 창으로 실행됩니다.

터미널에서는 이 폴더에서 `npm start`로 실행할 수 있습니다. 별도 패키지 설치가 필요하지 않습니다. 시작 스크립트로 실행한 서버는 `powershell -File .\Stop-AgentDesk.ps1`로 종료합니다.

## 다른 PC에서 시작하기

이 저장소를 새 PC에 복제한 다음, 그 PC에 Node.js 22 이상과 Codex CLI를 준비하고 Codex 계정으로 로그인합니다. 저장소는 공개되어 있어 GitHub 계정 로그인 없이 복제할 수 있습니다.

Windows PowerShell:

```powershell
git clone https://github.com/SHINBOGEUN/agent-desk-local.git
cd agent-desk-local
codex login
codex login status
Start-AgentDesk.cmd
```

macOS 또는 Linux 터미널:

```sh
git clone https://github.com/SHINBOGEUN/agent-desk-local.git
cd agent-desk-local
codex login
codex login status
npm start
```

서버가 시작되면 `http://127.0.0.1:4317`을 엽니다. macOS·Linux에서는 터미널에서 서버를 실행한 채 사용하고, 종료할 때 `Ctrl+C`를 누릅니다. 앱은 `data/`에 PC별 설정과 작업 기록을 저장하며 이 폴더는 Git에 올라가지 않습니다. 새 PC에서는 Codex에 다시 로그인하고 프로젝트 폴더를 다시 연결해야 합니다. 에이전트 설정이나 작업 기록까지 옮기려면 두 PC의 Agent Desk 서버를 종료한 뒤 `data/`를 별도로 안전하게 복사해야 합니다. 이 앱은 현재 Windows에서 실행과 검증을 마쳤고, macOS·Linux 실행은 아직 검증되지 않았습니다.

## 사용

- 프로젝트 폴더를 연결하고 메인 AI에게 요청합니다. 첫 프로젝트는 상위 AI_Agent 폴더이며 기본 권한은 읽기 전용입니다.
- 요청 입력창에 이미지(PNG·JPEG·WebP)를 Ctrl+V로 붙여넣거나 **＋ 이미지** 버튼으로 선택할 수 있습니다. 최대 3장, 장당 5MB이며 전송 전에 미리보고 제거할 수 있습니다. 이미지만 보내는 것도 가능합니다. 첨부 이미지는 메인 AI에게 전달되고, 팀원이 직접 봐야 할 때만 메인 AI가 해당 팀원에게 전달합니다. 이미지는 이 PC의 `data/attachments/`에 저장됩니다.
- 대화 입력창의 **요청 정리 AI 거치기** 스위치는 기본적으로 꺼져 있습니다. 끄면 원문을 바로 메인 AI에 전달합니다. 켜면 읽기 전용 프롬프트 정리 AI(GPT-6 Luna · Low)가 원문을 짧게 정리한 뒤 원문과 정리본을 함께 전달합니다. 원문이 우선이며 새 요구나 권한을 추가하지 않도록 지시합니다. 정리에 실패하면 원문으로 계속 진행합니다. 정리 단계에도 토큰이 사용되며 결과와 사용량은 작업 기록에 남습니다.
- 파일을 만들거나 수정하려면 프로젝트 설정에서 **실행 담당 에이전트의 파일 수정 허용**을 선택합니다. 에이전트에도 파일 수정 권한이 있어야 합니다.
- 반복되는 명령 실행 확인을 줄이려면 프로젝트 설정에서 **이 프로젝트에서 명령 자동 실행**을 켭니다. 파일 수정 권한이 있는 담당자의 프로젝트 내부 명령은 Codex `workspace-write` 범위에서 승인 요청 없이 실행됩니다. 메인 AI와 읽기 전용 팀원은 읽기 전용 범위를 유지하며 필요한 명령 승인은 Codex 자동 검토로 처리합니다. 프로젝트 밖 파일·네트워크 접근까지 허용하는 설정은 아닙니다. 기존 **현재 팀원 실행에서 허용**은 새 팀원 작업이나 다음 요청으로 이어지지 않습니다.
- 메인 AI가 `agent_desk_run` 도구로 등록된 에이전트에게 작업을 맡깁니다. 단순 대화는 직접 처리합니다. 위임을 확인하려면 “리서처에게 조사시키고 체커에게 검증시켜 줘”처럼 요청합니다.
- 단순한 서비스 실행·중지나 상태 조회처럼 지속되는 결과물을 바꾸지 않는 요청은 담당자가 직접 확인해 보고하며 체커를 별도로 호출하지 않습니다. 파일 수정 권한이 있는 역할에 이런 작업을 맡길 때도 메인 AI가 `readOnly: true`로 실행합니다. 코드·설정·문서·데이터 등 결과물을 변경한 작업은 마지막 변경 뒤 체커에게 독립 검증을 맡깁니다. 사용자가 명시적으로 체커 검증을 요청한 경우에도 호출할 수 있습니다.
- 팀원은 작업 중 API 계약·화면 동작·데이터 구조처럼 맞춰야 할 사항을 `agent_desk_ask`로 다른 활성 팀원 역할에 질문하고 답을 받아 계속 진행할 수 있습니다. 질문과 답은 같은 요청의 협의 기록에 남으며, 관련 팀원은 `agent_desk_inbox`로 확인할 수 있습니다. 작업 상세에서 협의 내용을 볼 수 있습니다. 답변은 상대 역할의 별도 읽기 전용 상담 턴에서 생성되므로 상대의 진행 중인 작업 스레드 기억을 직접 공유하지 않습니다. 현재/최근 배정 작업과 앞선 협의 내용을 맥락으로 전달합니다. 한 요청에서 최대 12회까지 협의할 수 있고 상담 턴의 사용량은 요청 전체 토큰 사용량에 포함됩니다.
- 후속 작업에 선행 결과가 필요하면 메인 AI가 완료된 팀원 작업의 ID를 지정해 보고를 인계합니다. 같은 요청에서 완료된 보고만 최대 3개, 각 1,800자까지 전달하고 작업 기록에 인계 출처를 남깁니다. 진행 중에는 흐름도에 팀원 간 인계선이 표시됩니다.
- 에이전트 메뉴에서 역할, 모델, 추론 수준, 지침, 활성화 여부를 설정하고 팀원을 추가할 수 있습니다. 메인 AI는 GPT-6 Sol · High, 새 팀원은 GPT-6 Luna · High로 시작하며 모델 이름과 슬라이더를 눌러 각각 변경할 수 있습니다.
- 왼쪽 메뉴의 **스킬**에서 반복 작업 절차를 재사용 지침으로 관리합니다. 스킬을 만들거나 편집할 때 사용할 팀원을 골라 연결하세요. 연결된 스킬은 해당 에이전트가 다음 작업부터 받으며 다른 팀원에게는 전달하지 않습니다. 기본 스킬은 필요한 범위만 탐색, 근거 기반 검증, API·데이터 계약 조율, 안전한 DB 변경, 보안 점검, 실제 화면 확인, 서버·인프라 변경 점검입니다. 메인 AI와 요청 정리 AI는 작업 스킬을 받지 않습니다. 스킬은 Agent Desk의 `data/state.json`에 저장되는 앱 내부 작업 절차이며 Codex의 전역 SKILL.md 설치와는 별개입니다. 같은 PC에서 연결한 모든 프로젝트에 적용됩니다.
- 파일 변경을 체커가 `FAIL`로 판정하면 메인 AI가 지적의 파일과 선행 작업 ID를 따라 원래 변경 담당자에게 해당 문제만 수정 요청하고, 체커에게 다시 독립 검증을 맡깁니다. 수정·재검증은 최대 2회이며 원인 담당이 불명확하거나 검증할 수 없는 문제는 임의로 재배정하지 않고 `검토 필요`로 보고합니다.
- **AI 모니터링 에이전트**는 에이전트 메뉴의 ‘운영 점검 요청’을 눌러 메인 AI에게 요청할 때 실행됩니다. 같은 프로젝트의 최근 요청 최대 8건에 대한 위임, 상태, 토큰, 검증 결과와 현재 팀 지침을 축약해 확인합니다. 근거가 있는 개선안만 최대 3개까지 메인 AI가 `agent_desk_update_guidance` 도구로 저장하며, 개선이 없으면 지침을 바꾸지 않습니다. 평소 요청마다 모니터를 호출하지 않아 추가 AI 사용량을 피합니다.
- ‘운영 점검 요청’은 대시보드의 통계 아래에서도 누를 수 있습니다. 버튼은 요청 문구만 입력하며 전송 버튼을 눌러야 실행됩니다.
- 모니터가 제안한 짧은 운영 지침은 에이전트의 기본 작업 지침과 별도 필드에 저장됩니다. 에이전트 설정에서 읽고, 고치거나 비울 수 있습니다. 저장된 지침은 다음 작업부터 적용되며 기존 운영 지침을 계속 덧붙이지 않고 교체합니다.
- 작업 상세에서 팀원별 보고, 실행 명령, 검증 결과와 실패를 확인합니다. 실시간 활동에는 실제 Codex 이벤트만 표시합니다.
- 중단·실패·검토 필요 작업은 대화 또는 작업 상세의 **이어서 실행**으로 다시 시작할 수 있습니다. 사용률 제한으로 중단된 작업에는 현재 누적 사용률을 반영한 **한도 추가 후 이어서 실행** 버튼도 표시됩니다. 추가 폭은 5%p 단위이며, 버튼에 적용할 증가량과 새 한도가 함께 표시됩니다. 이전 실행 기록과 완료·미완료 보고를 메인 AI에 인계하며, 현재 파일 상태를 확인한 뒤 남은 작업을 진행하게 합니다. 이전 실행 기록은 그대로 남고 새 실행이 연결됩니다.
- 작업 상세에는 중단 사유와 에이전트별로 보고된 토큰 합계·비율을 표시합니다. 토큰 보고가 없는 작업은 미보고로 표시합니다. 5시간 한도 사용률은 계정 전체 수치라 에이전트별로 분해할 수 없습니다.
- 작업 상세에는 `요청 분석 → 팀 작업 → 검증 → 최종 보고` 흐름이 표시됩니다. 파일 수정 권한을 실제 사용한 요청은 마지막 변경 이후 체커의 `[검증 결과: PASS]` 보고가 있어야 완료로 표시됩니다. 검증이 빠졌거나 실패하면 `검토 필요`로 남습니다.
- Codex가 실행 확인이나 질문을 보내면 대화창 안에 표시합니다. 지원하지 않는 외부 앱의 확인 양식은 거절합니다.
- 환경 설정에서 동시 실행 수, 위임 횟수, 실행 시간과 요청당 5시간 한도 사용률 증가 제한을 조절합니다.

## 범위와 저장

이 대시보드에서 시작한 작업을 관리합니다. 기존 Codex 앱 대화나 다른 프로그램의 에이전트 상태를 자동으로 가져오지는 않습니다. 브라우저를 닫아도 서버가 켜져 있으면 진행 중인 작업은 계속됩니다. PC 종료·서버 재시작 때 중단된 작업은 중단 상태로 복구되며 자동 재실행하지 않습니다.

현재 실행과 검증은 Windows에서만 완료했습니다. macOS·Linux는 Node 서버와 Codex CLI를 이용할 수 있는 구조지만, 시작·종료 스크립트와 파일 작업을 해당 운영체제에서 검증해야 합니다. 별도의 설치 프로그램이나 다중 사용자 로그인은 아직 없습니다.

화면과 작업 기록은 로컬에서 운영되며 AI 추론에는 인터넷과 현재 Codex 계정의 사용량이 필요합니다. 기존 Codex 인증을 CLI가 관리하며 이 앱은 로그인 토큰을 복사하거나 웹에 노출하지 않습니다. 이 버전은 개인 PC에서 사용하는 로컬 앱입니다.

`data/state.json`에 프로젝트별 대화·작업 기록(최근 60개), 품질 확인 판정, 에이전트 지침·모델·추론 수준, 앱 내부 재사용 스킬과 에이전트별 연결 설정을 저장합니다. 각 요청의 메인 AI에는 동일 프로젝트의 최근 완료 대화 3개를 최대 6,000자로 전달합니다. 팀원에게는 해당 작업 지시와 메인 AI가 지정한 선행 보고만 전달합니다. 장기 기억이나 모든 대화의 완전한 기억을 제공하지 않습니다. Codex 로그인 토큰은 이 파일에 저장하지 않지만, 지침이나 작업 요청에 민감한 내용을 직접 입력하면 파일에 남을 수 있습니다. `data/`는 공유하지 마세요.

토큰은 Codex가 보고한 스레드별 사용량을 합산해 참고용으로 표시합니다. 캐시 입력과 추론 토큰을 포함하는 총사용량이며 금액 또는 계정 사용률과 직접 환산되지 않습니다. 토큰 개수로 실행을 중단하지 않습니다.

요청 시작 직전 Codex 계정의 5시간 한도 사용률을 읽고, 실행 중 5초마다 갱신해 현재 5시간 창의 시작점 대비 증가분을 비교합니다. 설정한 증가량의 70%와 90%에 도달하면 경고하고 제한값에 도달하면 중단합니다. 실행 중 5시간 창이 갱신되면 새 창의 사용률을 기준으로 추적을 계속합니다. 사용률을 확인할 수 없거나 5시간 한도 정보가 예상과 다르면 요청을 시작하지 않거나 진행 중인 요청을 중단합니다. 계정 전체의 변화량이므로 다른 Codex 작업의 사용량도 포함될 수 있고, API 갱신이 늦으면 제한값을 일부 초과할 수 있습니다.

같은 5시간 창에서 이어하기를 실행하면 원래 요청의 기준점부터 사용률을 누적합니다. 이미 제한값에 도달했다면 한도 중단 기록의 추가 버튼을 누르거나, 창이 갱신되거나, 환경 설정의 제한값을 높여야 시작할 수 있습니다. 버튼은 현재 계정 사용률을 원래 기준점과 비교해 약 5%p의 실행 여유가 생기는 5%p 단위 증가량을 제안합니다. 다른 Codex 작업의 사용량이 늘었다면 처음 예상한 +5%p보다 큰 증가량이 필요할 수 있습니다. 추가는 그 작업의 이어진 실행에만 적용되고 전체 기본 설정은 그대로입니다. 실행 직전에 계정 잔여량이 5% 미만이거나 제안 한도를 수용할 잔여량이 부족하면 거절합니다. 오래된 기록도 측정 시각으로 같은 창임을 확인할 수 있으면 누적합니다. 확인할 수 없는 기록이나 새 한도 창에서는 현재 사용률을 새 기준점으로 삼고 일반 이어서 실행을 이용합니다. 이어하기는 새 AI 실행이므로 이전 실행의 메모리 상태를 그대로 복원하지는 않습니다.

대시보드는 선택 프로젝트와 수정 권한, 이번 요청의 5시간 한도 사용률 증가분을 대화창 아래에 표시합니다. 단순한 예산 충분 여부 질문에는 설정값과 최근 실측 기록으로 직접 답하며 AI 실행 토큰을 쓰지 않습니다. 다른 요청에서 메인 AI는 `agent_desk_budget`으로 현재 수치와 같은 프로젝트의 최근 실행 수치를 확인할 수 있습니다. 이전 실행은 작업마다 다르므로 제한값 안에서 완료된다는 보장은 하지 않습니다. 팀원에게는 필요한 파일 범위만 읽고 중복 조사를 피하도록 안내합니다.

쓰기 작업이 포함된 배치는 순차 실행하고, 읽기 작업은 설정한 수만큼 병렬 실행합니다. 서로 다른 배치에서도 쓰기 작업은 다른 팀원 작업과 겹치지 않습니다. 같은 에이전트에게 작업을 중복 배정하지 않습니다. 메인 AI와 기본 조사·검증 담당은 읽기 전용입니다. 등록된 에이전트는 Codex의 별도 임시 스레드로 실행되며, 내부 재위임은 비활성화해 모니터링되지 않는 팀원이 생성되지 않게 합니다.

## 개발과 검증

```powershell
npm run check
npm test
node scripts/probe.mjs
```

`AGENT_DESK_PORT`(기본 4317), `AGENT_DESK_DATA`(기록 저장 폴더), `AGENT_DESK_CODEX`(Codex 실행 파일 경로)로 실행 환경을 바꿀 수 있습니다. 서버는 `127.0.0.1`에만 바인딩하고 같은 출처와 실행 시 생성한 요청 토큰을 확인합니다. 다른 PC나 모바일 접속은 이 버전의 범위에 포함하지 않습니다.

Codex app-server의 실험적 동적 도구 인터페이스를 사용합니다. CLI 업데이트 시 연결 검사가 필요할 수 있습니다. 이 PC에서 확인한 버전은 `codex-cli 0.162.0-alpha.17.2`, Node.js `v24.19.0`입니다.

공식 프로토콜: https://learn.chatgpt.com/docs/app-server
