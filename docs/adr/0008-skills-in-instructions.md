# ADR 0008 · 스킬은 복사하지 않고 세션 지침에 목록으로 넣는다

- 상태: 채택 (2026-11-15, 사용자 지정)
- 관련: design-v2.md "스킬", "런타임 어댑터 계약", 로드맵 4-8, ADR 0004(점진적 공개)

## 결정
- 스킬 원본은 `.agent-desk/skills/<id>/SKILL.md`에 그대로 둡니다. 실행할 때 `.agents/skills`·`.claude/skills`로 **복사하지 않습니다.**
- `packages/project`의 `skillsByRole(project, loaded, onSkip?)`가 역할마다 쓸 스킬(`SkillRef`: id·description·SKILL.md 경로)을 정하고, `executeRun`이 이를 `RunConfig.skills`로 넘깁니다.
  - 역할은 자기 역할 파일(`.agent-desk/agents/<role>.md`)의 `skills`에 적힌 스킬만 받습니다.
  - `config.skills`가 있으면 그 목록에 있는 스킬만 씁니다(없으면 역할 파일 기준).
  - 존재하지 않거나 `skills check`에서 오류가 난 스킬은 빼고, 이유를 실행 전 안내(`note: skill "<id>" is not used: ...`)로 알립니다.
- 오케스트레이터는 세션을 열 때 `SessionOptions.skills`에 그 역할의 목록을 넣고, 지침(`instructionsFor`)에 "id: 설명 (SKILL.md 경로)" 목록과 사용 규칙(설명이 맞을 때만 SKILL.md를 읽고, 참조 파일은 본문이 가리킬 때만 읽음)을 붙입니다. 스킬이 없는 역할의 지침은 바뀌지 않습니다.

## 이유
- 설계서의 원칙 "설정의 원본은 하나, 하네스는 실행 중에 추적 파일을 쓰지 않는다"와 맞습니다. 복사는 사용자의 `.agents/`·`.claude/`(이미 다른 용도로 쓰는 경우가 많음)를 실행마다 건드리고, 원본과 사본이 어긋날 수 있습니다(v1에서 실제로 겪은 문제).
- 점진적 공개 1층(설명만 항상 맥락에 둠)은 지침 목록으로 그대로 됩니다. 2·3층(본문·참조 파일)은 모델이 파일 읽기로 합니다. 두 런타임 모두 프로젝트 안 파일을 읽을 수 있으므로(Claude는 ADR 0007의 읽기 정책 범위 안) 런타임별 처리 없이 한 가지 방식으로 됩니다.
- 역할별로 다른 스킬을 줄 수 있습니다. 런타임 폴더 배치는 세션마다 역할을 나누기 어렵습니다.

## 한계와 확인할 것
- 런타임 고유의 스킬 기능(Claude Code의 Skill 도구, Codex의 스킬 로딩)을 쓰지 않으므로, 모델이 "스킬"로 인식해 호출하는 경향이 약할 수 있습니다. 트리거 정확도와 스킬 유무 비교는 6단계 벤치마크에서 측정합니다.
- 설명 목록은 매 턴 비용입니다. `skills check`의 길이 경고(설명 합계 4,000자)를 그대로 따릅니다.
- 실제 모델이 목록을 보고 SKILL.md를 읽는지는 확인하지 못했습니다(가짜 런타임 테스트만 있음).
