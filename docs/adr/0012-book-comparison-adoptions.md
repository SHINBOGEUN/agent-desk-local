# ADR 0012: 책 예제 대조 후 가져온 것 — 리뷰 근거·재검토 축소·스킬 점검·기준선·품질 기록

- 날짜: 2026-11-17
- 상태: 결정
- 참고: 《하네스엔지니어링 with Claude Code》 예제 저장소(revfactory/harness-engineering-with-cc)의 md 128개, 사용자의 Notion "하네스" 정리 노트

## 배경

책의 원칙(근거 없는 지적 제외, 재호출은 바뀐 부분만, 스킬 분리 신호·안티패턴, With/Without 비교와 변별력 있는 단언, Phase 7 개선 루프)을 우리 코드와 대조했다. 책은 이것을 에이전트 지침(md)으로 요구하지만, 지침은 모델이 어길 수 있다. 우리 원칙("안쪽은 확률론적, 가장자리는 결정론적")대로 코드가 지키게 했다.

## 결정

1. **리뷰 지적의 위치 검사**(`findingLocationErrors`): verifier의 blocking 지적이 가리키는 파일이 있는지(변경으로 지워진 파일은 허용), 행 번호가 파일 안인지 확인한다. 파일이 없는 REDO 지적은 요구사항 ID나 요청을 근거로 대야 한다. 어기면 보고서를 반려해 같은 턴에서 고친다. 지어낸 위치로 REDO가 나면 builder 한 턴이 통째로 낭비되기 때문이다.
2. **REDO 후 재검토는 바뀐 부분만**: 재검토 프롬프트에는 이전 지적 목록과 그 뒤 바뀐 파일의 diff만 넣는다. verifier는 이전 지적마다 해결 여부를 판정하고, 지난 검토 뒤 바뀌지 않았고 이전 지적에도 없던 파일에 새 blocking 지적을 내면 반려한다(`staleFindingErrors`). 토큰을 줄이고 매번 새 지적이 튀어나오는 것을 막는다. 요구사항 근거의 지적(파일 없음)은 막지 않는다.
3. **verifier 지침**: 직접 본 것(파일 내용, 명령 출력)만 blocking, 추측은 optional에 추측이라고 표시.
4. **스킬 점검 보강**: 이유 없는 절대 규칙(ALWAYS/NEVER/MUST/반드시/절대 5개 이상, 이유 없음)을 경고로 올림. 요청 종류별 분기가 4개 이상인데 `references/`가 없으면 라우터+references 분리를 권고. `triggers.json`의 사례가 8개 미만이거나 한 언어뿐이면 알림(책 실험: 한국어 키워드만 쓴 스킬이 "Total Amount"를 놓침). Claude Code 전용 키(`disable-model-invocation` 등)는 오류가 아닌 정보로 표시. `init` 스킬 초안에 정상·에러 예시와 사례 8개씩.
5. **맨몸 기준선**: 벤치 `--adapter bare`가 하네스 없이 `codex exec`에 과제 문장만 넣는다. 하네스가 실제로 더하는 것(성공률·거짓 완료·토큰)을 숫자로 보인다. 보고서에 과제 변별력(라벨 간 결과가 다른 과제만 비교 가치), 근거 검사 반려 수, 1차 리뷰 대 재검토 토큰을 추가.
6. **품질 기록(Phase 7 개선 루프)**: 실행마다 👍/👎, 👎에는 고칠 곳(스킬/역할 파일/워크플로·설정/기타)과 파일·메모. 대시보드에서 그 파일을 바로 연다. 품질 기록 탭은 고칠 곳별 건수, 많이 지목된 파일, 워크플로별, 근거 검사 반려 수, REDO 실행 수, 👍/👎 평균 토큰을 보여주고 CSV/JSON으로 내보낸다(저장소 스키마 v4).

## 가져오지 않은 것

- 에이전트끼리 직접 메시지(SendMessage)와 8인 팀: 통신 경로가 늘면 비용과 실패 경로가 는다. 우리 구조(lead 라우팅 + 생성·검증, 4역할)가 목표에 맞다.
- "불확실하면 REDO", "2회 REDO 후 경고와 함께 PASS": 사용량·환각 목표와 반대. 우리는 불확실하면 BLOCKED, 상한 도달 시 needs_review.
- URL 출처 실제 조회 검사: 런타임이 웹 조회 이벤트를 남기지 않아 결정론적으로 확인할 수 없다. 후보로 남긴다.

## 책 저장소에서 확인한 오류(우리에게 영향 없음)

`type: general-purpose`는 공식 frontmatter 필드가 아님, `AgentTool`은 실제 이름이 아님(`Agent`), `Bash(gh pr diff, gh pr comment)` 권한 문법 오류, refactorer가 Edit만으로 새 diff 파일을 만들려 함(Write 필요), 결과물 대부분이 mock/dry-run 예상치. 우리는 문법이 아니라 원칙만 가져왔다.

## 확인 방법

PC 측정: `--set hard`처럼 REDO가 나는 과제에서 "리뷰 토큰: 1차 → 재검토"와 "근거 검사로 반려된 보고서", `--adapter bare` 대 v2 비교.
