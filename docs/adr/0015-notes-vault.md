# ADR 0015: 프로젝트 노트 볼트 (옵시디언 연동)

- 날짜: 2026-11-21
- 상태: 결정

## 배경

헤르메스(Nous Research)와 옵시디언을 검토했다(대화 기록: 2026-11-20). 헤르메스로 오케스트레이션을 옮기는 안도 따져 봤지만, Codex 런타임에서는 하네스가 중간 과정을 보지 못하고 완료 순간에만 검증할 수 있어 첫 번째 목표(할루시네이션 줄이기)가 약해진다. Claude 구독 연결도 실험 단계라 지금은 옮기지 않는다. 헤르메스는 나중에 벤치마크 비교 대상으로 측정한다.

대신 사람이 읽고 고치는 지식은 옵시디언 볼트(평범한 마크다운 폴더)로 둔다. 메모는 2,000자 목록 하나뿐이라 결정의 이유와 출처가 남지 않았고, 사용자가 쓴 기획을 에이전트가 읽을 통로가 없었다.

## 결정

1. **볼트 폴더**: `config.vault`(절대 경로, 또는 프로젝트 기준 상대 경로). 기본값은 `.agent-desk/notes`. 옵시디언에서 이 폴더를 볼트로 열거나, 기존 볼트 안의 폴더를 지정한다. 하위 폴더 4개: `specs/`(사용자 기획), `decisions/`(승인된 규칙과 이유), `inbox/`(승인 대기 메모 제안), `runs/`(실행 기록).
2. **실행 기록(모델 호출 0)**: 실행이 끝나면 하네스가 저장된 결과로 `runs/0056 <요청>.md`를 쓴다. 요구사항과 결과, 한 일, 되돌려진 이유, 변경 파일 `[[링크]]`, 게이트, 리뷰, 쓰인 스킬, 메모 제안 링크가 들어간다. 볼트 문제는 경고만 남기고 실행 결과를 바꾸지 않는다.
3. **메모 승인 흐름**: 메모 제안은 `inbox/` 노트(`status: proposed`)가 된다. 옵시디언에서 `status: approved`로 바꾸면 다음 실행을 시작하기 전에(메모를 읽기 전에) memory.md에 들어가고 노트는 `decisions/`로 옮겨진다. `rejected`는 `.trash/`로. 대시보드의 "메모에 추가"와 노트 화면의 "승인"도 같은 길을 탄다. memory.md에는 여전히 승인된 것만 들어간다.
4. **read_notes 도구**: lead와 builder의 지침에 읽을 수 있는 노트 제목 목록(최대 1,500자)만 넣고, 내용은 필요할 때 `read_notes`(경로 또는 검색어, 최대 4,000자)로 읽는다. `runs/`(read_history가 담당)와 `inbox/`(승인 전이라 사실이 아님)는 읽을 수 없다.
5. **기획 노트 인용 검사**: 요청이 기획 노트를 가리키면("specs/로그인대로 만들어줘") 요구사항은 그 노트를 인용하고 `source`에 경로를 적는다. 하네스는 인용이 그 노트에 실제로 있는지 코드로 대조한다(요청 원문 인용 검사의 확장). 답변의 근거로 노트를 들 수도 있다.
6. **변경 감지 제외**: 볼트가 프로젝트 안에 있으면 그 경로는 변경 파일 확인(G2)과 보호 경로에서 뺀다. 사용자가 실행 중에 옵시디언에서 노트를 고쳐도 실행이 실패하지 않게 하기 위해서다. 그 대신 에이전트가 노트를 고쳐도 감지되지 않으므로, 메모와 규칙은 노트가 아니라 승인 흐름으로만 바뀐다.
7. **대시보드 노트 화면**: 링크 그래프(직접 만든 결정적 힘 배치, 외부 라이브러리 없음), 폴더별 목록, 편집기(링크 넣기, 새 노트, 이름 바꾸기, 휴지통, 제안 승인), 나가는·들어오는 링크. 저장할 때 파일이 그 사이 다른 곳(옵시디언)에서 바뀌었으면 덮어쓰지 않고 다시 불러오게 한다.

## 버린 것

- 에이전트가 기억과 규칙을 직접 쓰는 헤르메스식 자기 학습: 착각이 영구 규칙이 된다. 제안 → 승인만 둔다.
- 볼트 전체를 지침에 넣기: 사용량이 커진다. 제목 목록과 필요할 때 읽기만.
- 노트 이름을 바꿀 때 다른 노트의 링크 자동 수정: 옵시디언에서 하면 된다. 대시보드는 경고만.

## 측정 (PC)

기획 노트를 쓰고 "specs/…대로 만들어줘"로 요청했을 때 lead가 `read_notes`로 읽고 `source`를 붙이는지, 인용 검사가 지어낸 요구사항을 막는지, 노트 목록이 지침에 더하는 토큰(제목 목록 크기 정도)을 확인한다.

## 추가 (2026-11-21): team 노트와 기존 기록 가져오기

- **team/ 노트(읽기 전용 거울)**: `team/roles/<역할>.md`와 `team/skills/<스킬>.md`를 역할 파일과 스킬에서 자동으로 만든다(`generated: true`). 역할 → 스킬 링크, 스킬 → 쓰는 역할, 스킬이 실제로 읽힌 실행(하네스가 기록한 `skillsRead`, 최근 200개 실행)과 횟수가 들어간다. 원본은 그대로 `.agent-desk/agents`, `.agent-desk/skills`이고 수정은 설정에서 한다. 실행 시작·끝과 노트 화면을 열 때 다시 만들며, 내용이 같으면 파일을 건드리지 않는다. 없어진 스킬의 생성 노트만 지우고, 사용자가 team/에 쓴 노트는 두지 않고 건드리지도 않는다. 에이전트의 `read_notes` 대상에서는 뺀다(이미 지침으로 받는 내용).
- 이유: 개발자들은 보통 에이전트 설정을 코드 쪽에 원본으로 두고 볼트에는 목차(MOC) 노트나 심볼릭 링크를 둔다. 스킬 파일 이름이 모두 SKILL.md라 링크로 구분할 수 없고 윈도우 심볼릭 링크는 권한이 필요해, 하네스가 관리하는 목차 노트로 한다. 사람이 만드는 목차가 비어 버리는 문제도 없다.
- **실행 기록 노트**에 참여한 역할(`[[team/roles/builder|builder]]`, 쓴 모델)과 읽은 스킬 링크를 넣어 그래프가 실행 → 역할 → 스킬로 이어진다. 연결이 없는 스킬 노트는 한 번도 안 쓰인 스킬이다(헤르메스 큐레이터의 사용 추적).
- **기존 기록 가져오기**(노트 화면 버튼, `POST /api/notes/import`): 노트 폴더 전의 실행마다 저장된 보고서로 실행 기록 노트를 만들고(게이트 정보는 저장돼 있지 않아 빠짐), memory.md의 규칙마다 결정 노트를 만든다. 모델 호출 없음, 반복해도 중복 없음.
