# ADR 0013: 보고서가 접수되면 하네스가 턴을 끝낸다

- 날짜: 2026-11-18
- 상태: 결정 (PC 확인 필요)

## 배경

실행 #39(인사 한 줄, answer 흐름)의 사용량: lead 한 단계에 모델 호출 3번, 호출마다 약 13k 입력(Codex 기본 지침·도구 정의·역할 지침). 세 번째 호출은 보고서가 접수된 뒤 모델이 마무리 한마디(24토큰)를 하는 호출로, 하네스는 그 말을 쓰지 않는다. 이 호출은 모든 실행의 모든 단계(분류·계획·빌드·리뷰·조사)에서 생긴다.

## 결정

- `submit_report`가 보고서를 접수하면(같은 턴에서 고칠 반려가 아니라 최종 접수) 도구 응답이 나간 직후(`setImmediate`) 그 턴을 중단한다. Codex는 `turn/interrupt`, Claude는 interrupt 제어 요청이다. 세션은 닫지 않으므로 같은 세션 재작업과 자체 점검 리뷰는 그대로 쓸 수 있다.
- 이렇게 끝난 턴은 `interrupted`가 아니라 `completed`로 처리한다. 사용자가 실행을 멈춘 경우는 그대로 `interrupted`.
- 반려된 보고서는 턴을 끝내지 않는다(같은 턴에서 고쳐야 하므로).
- 부수 효과: 보고 뒤에 파일을 더 바꾸는 일도 막힌다.
- 대시보드 역할별 표에 모델 호출 수, 새 입력, 캐시 입력, 출력을 나눠 보인다. 합계만으로는 실제 비용과 낭비 위치가 보이지 않는다.

## 효과와 한계

단계마다 모델 호출 1번(이번 예에서는 40k 중 13.5k)을 줄인다. 다만 그 호출의 입력은 대부분 캐시 입력이라 실제 비용 절감은 합계 숫자보다 작다. 중단 요청이 모델의 다음 요청보다 늦게 도착하면 그 호출은 일부 진행될 수 있다.

## 확인 방법

PC에서 같은 요청을 다시 실행해 역할별 표의 모델 호출 수가 줄었는지, 같은 세션 재작업(REDO 1회차)과 `--review self`가 정상인지 본다.

## PC 확인 결과 (2026-11-18, 실행 #40 "안녕")

- 상태 `completed`, lead 모델 호출 1번(입력 13,055 중 캐시 11,264, 출력 51). 보고 직후 턴이 끝났다.
- 대시보드는 26k로 보였는데, Codex가 턴 중단 때 직전 사용량 알림을 한 번 더 보내 이중 집계된 것이었다(같은 값, 5ms 뒤). 스레드 누적 합계(`total`)가 그대로인 반복 알림은 세지 않도록 고쳤다(`usageTotalOf`). 실제 사용량은 약 13k.
