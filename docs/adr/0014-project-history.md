# ADR 0014: 프로젝트 기억 — 누적 요약과 필요할 때 찾아보기

- 날짜: 2026-11-19
- 상태: 결정

## 배경

실행마다 세션을 새로 열고, 직전 실행 하나의 요약만 lead 분류 단계에 넘겼다. 프로젝트 하나를 여러 날 개발하면 매번 맥락을 다시 설명해야 했다. 대화 전체를 이어 붙이는 방식(일반 채팅)은 호출마다 전부 다시 보내므로 실행할수록 비용이 커진다(v1에서 메인 맥락이 197k → 1,901k로 불어난 원인).

## 결정

일반 채팅의 "길어지면 요약"과 "문서는 필요할 때 읽기"만 가져온다.

1. **누적 요약(항상)**: 실행이 끝날 때 이미 코드로 만드는 실행 요약(brief)을 모아 `projectHistory`로 만든다. 최근 2개는 전체, 그 이전은 한 줄(요청 → 결과, 변경 파일), 최대 2,000자. lead와 builder의 지침에 넣는다. verifier는 독립 판정을 위해, researcher는 자기 관점만 보도록 받지 않는다. 모델 호출 없이 만들어지므로 요약 비용은 0, 전달 비용은 실행당 최대 약 2,000자.
2. **찾아보기(필요할 때만)**: `read_history` 도구(실행 번호 또는 검색어). 저장된 요약과 보고서에서 요구사항, 작업 요약, 요구사항별 결과, 실행한 명령, 리뷰 지적, 답변을 돌려준다(최대 4,000자, 같은 프로젝트만). 쓰지 않으면 비용이 0이다.
3. **프로젝트 메모(기존)**: 계속 유효한 사실은 사용자가 승인해 `.agent-desk/memory.md`에 둔다.
4. 이어하기(resume)는 그대로 중단된 실행의 요약을 분류 단계에 넘긴다.

## 측정

PC에서 이어지는 요청("아까 만든 것에 ...")으로 lead가 대상을 맞히는지, `read_history` 호출이 필요한 경우에만 생기는지, 실행당 토큰 증가가 요약 크기 정도인지 확인한다.

## PC 확인과 보강 (2026-11-19)

- mecro 프로젝트: "아까 만든 날짜, 굵게 해줘"를 lead가 직전 작업으로 이해했고 builder가 그 스타일 문자열만 고쳤다. "처음에 했던 작업?"은 요약만으로 답했고 `read_history`는 쓰지 않았다(호출 1번). lead 호출당 증가는 약 1k(13k → 14k, 대부분 캐시).
- 보강: 사용자가 말한 결정(라이브러리·규칙·한도)과 이유도 메모 제안으로(builder, 그리고 질문으로 분류된 경우 lead). `read_history`는 보고서 본문까지 검색하고, 모든 단어가 맞는 실행이 없으면 일부가 맞는 실행을 순서대로 돌려주며, 한·영을 함께 넣으라고 안내한다.
