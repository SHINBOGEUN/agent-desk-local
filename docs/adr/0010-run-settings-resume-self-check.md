# ADR 0010: 실행 설정 기록, 이어하기, 자체 점검 리뷰, 런타임 대체, 대시보드 편집

- 날짜: 2026-11-17
- 상태: 결정 (사용자 결정: 대시보드에서 직접 저장, 스킬 초안, 이미지 첨부 필요)

## 결정

1. **실행 설정 기록**: Run마다 시작할 때의 설정(모드, 역할별 런타임, 리뷰 정책, verify, 역할별 스킬, 모델·effort, 한도, 이미지 수, 이어하기 대상, 안내 문구)을 `runs.settings`(스키마 v3)에 남긴다. 결과가 어떤 설정에서 나왔는지 나중에 확인하기 위해서다(설계서의 "설정 스냅샷").
2. **이어하기**: `resume <run id>`, `POST /api/runs {resumeOf}`, 대시보드 "이어서 하기". 이전 세션을 재사용하지 않고, 새 Run에 이전 Run의 요약과 끝나지 않은 요구사항, 멈춘 단계를 이전 요약 자리(`previousBrief`)로 넘긴다. 이미 바뀐 파일은 그대로 두고 확인하게 한다.
3. **자체 점검 리뷰(`review: self`)**: 측정용(로드맵 3-5). G4에서 새 verifier 세션 대신 builder 세션이 같은 세션에서 자기 작업을 verifier 형식으로 다시 점검한다. 파일을 바꾸면 읽기 전용 위반으로 `needs_review`. 기본값 후보가 아니라 "두 명이 한 번씩 보는 것"과 비교하기 위한 구성이다.
4. **런타임 대체**: 팀이 강제되지 않았을 때(`--runtime`, `--mode`, 대시보드 선택이 없을 때) 시작 전에 Codex 5시간 사용률이 `limits.switchAtCodexPercent`(기본 95, 0이면 끔) 이상이고 Claude가 설치되어 있으면 Codex 역할을 Claude가 맡는다. 실행 중 교체는 하지 않는다(세션 중간 교체는 맥락이 끊김). 벤치마크는 `--mode`를 명시하므로 영향을 받지 않는다.
5. **대시보드 편집**: `.agent-desk/config.json`, 역할 파일, 스킬을 대시보드에서 파일 그대로 편집한다. 저장 전에 임시 폴더에서 하네스와 같은 검사(설정 검증, 역할 파일 파싱·읽기 전용 역할 보호, 스킬 구조 검사)를 돌리고 오류가 있으면 쓰지 않는다. 같은 프로젝트에서 실행 중이면 저장을 막는다.
6. **이미지 첨부**: 요청당 4장, 장당 5MB, PNG·JPEG·WebP·GIF. 데이터 폴더 `attachments/`에 저장하고, 요청을 읽는 각 단계(classify, plan, build, research)의 첫 프롬프트에만 붙인다. 리뷰에는 붙이지 않는다(리뷰는 요구사항과 실제 변경으로 판단).
7. **Claude 사용량**: Claude Code가 계정 한도 비율을 알려주지 않으므로, 이 PC에서 Agent Desk가 Claude 역할에 쓴 토큰(최근 5시간·7일)만 보여준다.
8. **검증 도구**: `run --dry-run`(모델 없이 팀·검증·스킬 점검), `--no-skills`(스킬 유무 비교), `skills trigger-test`(스킬 폴더의 `triggers.json`으로 should/should-not 사례를 각각 새 세션에서 물어 적중률·오발동률 측정), 벤치 분류 정확도(3-6), `bench/failures.mjs`(실패를 스킬·역할 파일·워크플로·환경으로 분류, 6-5).
